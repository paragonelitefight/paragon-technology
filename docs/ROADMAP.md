# Experimental showcase / Earn the attention

> **19 November 2026 status:** This page preserves the original proposal list, not a current all-unimplemented inventory. A bounded Experimental Lab 1.3 is now implemented and served under public presentation release 1.3.1, including synthetic markets, typed evidence exercises, symbolic artwork, fictional-event inspection and supported receipt replay. See the [implemented scope](CONNECTED_RELEASE_2026-11-19.md) and [acceptance boundaries](ACCEPTANCE_2026-11-19.md). This does not establish completion of every distinct proposal below. In particular, the round timer remains deferred, and a signed-proof laboratory or reference-graph explorer must not be inferred from the new evidence exercises. No external archive deposit for this documentation update is claimed before confirmation.

Documentation baseline: 16 November 2026. The entries below are proposals, not deployed features or delivery commitments.

## Architecture explorer

A navigable view of the existing systems map, showing responsibilities, public evidence paths and lifecycle labels. It must not fabricate live health, expose private topology or imply every component has equal implementation maturity.

## Proof laboratory

An educational demonstration contrasting an unchanged signed record with a deliberately modified local copy. Any future demonstration must label fixtures, avoid production writes and distinguish invalid signatures from unsupported browser cryptography. It is not yet implemented by this documentation package.

## Reference-graph lens

A focused exploration of the dated public graph, with dataset version and no live-price or stock claims. An earlier Graph Explorer initiative is parked; this proposal does not authorize rebuilding it.

## Round timer or embeddable sizing

Choose a genuinely useful visitor tool after checking existing assets. A sizing interface should reuse reviewed existing data rather than create conflicting charts. Timer design would need timing, accessibility and background-tab behaviour checks. Neither tool is supplied here.

## Publication workbench

Extend the existing reviewed-release-to-publication pattern with clearly bounded examples, evidence ledgers and controlled presentation updates. The current implementation does not automatically update all storefront pages or Knowledge Base answers.

## Distribution

Potential future channels include a reviewed technical-report deposit, software archiving, selected developer communities and relevant social publishing. Each requires a real release, appropriate attribution and a separate destination decision. No new DOI, archive deposit, social account, external submission or scheduled publication is created by this roadmap.

## Acceptance principles

Useful or educational purpose; explicit experimental label; no invented measurements; no automatic source approval; no hidden tracking by default; bounded performance and cost; reversible integration; preserved commerce and signed identity.
