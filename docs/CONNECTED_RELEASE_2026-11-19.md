# Connected commerce and Experimental Lab

Documentation date: 19 November 2026. Proposed documentation edition: v0.2.0.

## A storefront with an inspectable technical layer

Paragon connects boxing and BJJ equipment information with source-linked documentation, supplementary shopping interfaces and bounded computational experiments. The useful question is not whether a system looks advanced, but what a reader can inspect, reproduce and distinguish from an untested claim.

## Three execution domains

1. Scheduled server work advances bounded Living and Temporal state and collects selected source categories through the existing clock infrastructure. This is not a promise of uninterrupted execution or an exact whole-site refresh interval.
2. Request-driven readers expose catalog and page representations with explicit cache and fallback boundaries. Reading an endpoint is not the same operation as collecting a complete new source cycle.
3. User-initiated browser workbenches run experiments and export receipts. Local fiction, markets and reasoning demonstrations do not become continuously autonomous server worlds.

## Experimental Lab 1.3, public presentation 1.3.1

[Open the Lab](https://paragonelitefight.com/experimental-lab).

The integrated release adds a synthetic multi-participant market with budgets, inventory, trade events, conservation checks and deterministic replay; typed evidence exercises with exact captured-quotation anchors, scoped assertions and reviewer-assigned support/counter hypotheses; premise-driven symbolic artwork; and a fictional-event timeline inspector. A common local dossier can combine up to eight supported receipts after recomputation. Earlier Depth workbenches and accepted receipt compatibility are retained.

The market trades synthetic units and tokens, not money or real inventory. Exact quotation anchoring does not establish semantic truth or independently authenticate the source. Logical conflicts depend on the declared scope and semantics. Fictional events are simulations, not real-world observations.

The browser includes an optional bounded GPU Gram-matrix exercise. This documentation does not independently verify a device screenshot or establish a general GPU platform, numerical guarantee across devices or broad device acceptance.

Public presentation 1.3.1 changes release and indexing metadata, not the accepted experiment engines or scheduled state logic.

## Source collection and publication boundaries

The collector separates staged pages from published complete-category heads. It uses bounded pagination, content-addressed objects, conditional publication, leases and reconciliation of ambiguous writes. Failure handling is category-scoped and does not silently turn missing or corrupt input into successful evidence. These mechanisms are implementation descriptions, not claims that every production failure path has been observed.

A completed 24-product category was observed on 19 November. At that checkpoint the four other source categories had not yet published new complete cycles. This is not evidence of a complete five-category refresh, retention throughput or Workers Free CPU capacity under every condition.

## Shopping and machine-readable pages

The supplementary adapter version 2.2.0 exposes eight tools: six guidance/reference tools plus paragon_prepare_purchase and paragon_create_cart. A bounded one-cart handoff was tested on 18 November; that test did not open checkout or place an order. Native commerce, payment authorization and checkout retain their own responsibilities.

ProductSync 2.1 acceptance was scoped to one three-variant product, two country contexts and selected JSON, Markdown and recommendation representations. It was not a whole-catalog or all-market certification.

PageSourceSync 1.1 covers eight canonical pages through request-driven reads, a five-minute cache and a labelled last-good fallback ceiling of 24 hours. It does not automatically publish native Knowledge Base facts, update GitHub or Zenodo, rewrite signed historical records or control external AI answers. The owned agents.md is a publisher-provided guide, not a universal instruction protocol.
